# HW1 — Dataset Splitting & Data Leakage

> 注意：Place the MNIST dataset under ./data/MNIST/ before running split_mnist.py.

專案中的 `dataset_loader.py` 目標在於正確地將 MNIST 資料集分割為訓練、驗證和測試集，並特別強調避免 Data Leakage。

## 什麼是資料洩漏 (Data Leakage)？

在機器學習中，**資料洩漏**是指在模型訓練過程中，不慎讓模型接觸到了來自訓練集之外的資訊。這是一個嚴重的問題，因為它會導致模型在評估指標上表現得過於樂觀，給人一種模型效果很好的假象。然而，當模型應用於從未見過的真實世界數據時，其表現會遠不如預期，因為它在訓練時「偷吃步」。

> 一個最典型的洩漏例子是**在分割資料集前就對整體資料進行預處理** 。例如，如果先對包含所有樣本的資料集進行標準化（Normalization），那麼驗證集和測試集的數據分佈資訊（如均值、標準差）就已經「洩漏」到了訓練集中，模型從中學到的規律在現實中是不成立的。

## 本專案如何避免資料洩漏

本專案透過嚴謹的程序設計，從根本上杜絕了資料洩漏的風險：

1. **立即分割 (Splitting First)**：我們的程式在讀取完所有圖片的檔案路徑後，**第一步就是執行分割** 。任何後續的數據轉換或預處理（如讀取圖片、像素正規化）都應在這三個獨立的集合上分別進行，確保驗證和測試集對於訓練過程是完全「未知」的。

2. **確保集合獨立互斥**：程式透過對每個類別的圖片列表進行切片（slicing）來分配樣本，這種機制保證了**同一張圖片絕不會同時出現在兩個或多個集合中** 。訓練、驗證和測試集是完全獨立、沒有交集的。

3. **實作洩漏檢查 (Verification)**：作為 Bonus，我們實作了 `check_data_leakage()` 函數 。該函數透過計算三個集合之間的路徑交集來進行驗證。執行結果顯示交集為空，從程式上再次確認了三個集合的樣本是完全獨立的，沒有發生資料洩漏。
